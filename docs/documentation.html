AWS Services

Five managed AWS services work together. You don't manage any servers.

🚪
API Gateway
The secure HTTPS front door. Routes browser requests to Lambda, handles CORS, throttles to 20 req/s.
HTTP API v2
⚡
Lambda
One Python function. Reads the PDF, calls Bedrock or Textract, writes a log. No servers, pay per invocation.
Python 3.12

Architecture

How it works — simple view

The browser sends a PDF and a schema; one Lambda decides which AI service to call and returns the JSON.

flowchart LR Browser["🌐 IDP Studio\nGitHub Pages"] GW["🚪 API Gateway\none HTTPS endpoint"] Lambda["⚡ Lambda\nhandler.py"] Bedrock["🧠 Amazon Bedrock\nClaude AI"] Textract["🔎 Amazon Textract\nOCR"] S3["🗄️ Amazon S3\nstore + logs"] Browser -->|"PDF + schema\n+ API key"| GW GW -->|"routes by\npath + method"| Lambda Lambda -->|"PDF → JSON"| Bedrock Lambda -->|"PDF → key/values"| Textract Lambda <-->|"store PDF\nwrite/read logs"| S3 Lambda -->|"structured JSON\nresult"| Browser
✅
No credentials in the browser. The static website only knows your API Gateway URL and an optional API key. All AWS calls happen inside Lambda with an IAM role.
Extraction Strategies

4 ways to extract data from a PDF

All 4 tabs return the same JSON shape — they just take different paths. Pick based on your document type.

Direct Bedrock Extraction

Best accuracy

Send the PDF bytes directly to Claude on Amazon Bedrock. Claude reads and understands the entire document in one shot and returns values shaped to your Target JSON schema.

1
Upload PDF — base64 encoded, sent in the request body
2
Lambda calls Bedrock Converse API — passes the PDF as a document content block
3
Claude returns JSON — matched to your target schema
4
Log written to S3 with PII masked if enabled
Best for
  • Any PDF type
  • Free-text content
  • Mixed documents
  • Highest quality output
Route
POST /v1/extract/bedrock
Typical latency
3–8 s

Textract OCR → Bedrock Mapping

Great for forms

First, Amazon Textract runs specialist OCR to pull out key/value pairs, checkboxes, and tables. Then Bedrock maps those raw pairs to your target schema. Two steps, best for structured forms.

1
Lambda uploads PDF to S3 — Textract requires S3, not direct bytes
2
Textract async analysis — polls until job succeeds (~5–15 s)
3
Raw key/values extracted — shown as "Raw Textract output" in the UI
4
Bedrock maps to schema — Claude reshapes the OCR pairs
Best for
  • Structured forms (tick-boxes, fields)
  • Tables with rows/columns
  • Documents where layout matters
  • When you need raw OCR output too
Route
POST /v1/extract/textract
Typical latency
15–40 s

Agentic Pipeline

Great for demos

A five-step pipeline where each agent has a visible input and output in the UI. Great for understanding the end-to-end flow or showcasing the capabilities.

1
📥 Ingest Agent — stores PDF in S3
2
🔎 OCR Agent — Textract extracts key/values
3
🛡️ PII Masking Agent — regex masks emails, phones, IDs
4
🧠 Extraction Agent — Bedrock maps masked data to schema
5
✅ Validation Agent — checks required schema keys are present
Best for
  • Demo / stakeholder presentations
  • Understanding the flow visually
  • Debugging which step fails
  • Showing PII masking in action
Route
POST /v1/agents/run
Typical latency
30–60 s

Azure Document Intelligence

Azure stack

Mirror of the AWS flow but running on Azure. Uses Azure Document Intelligence (formerly Form Recognizer) for layout extraction, then Azure OpenAI to map to your schema.

1
Azure Function receives request — similar to Lambda
2
Document Intelligence analyzes PDF — layout, tables, key/values
3
Azure OpenAI maps to schema — GPT-4o model
4
Log written to Azure Blob Storage
Best for
  • Azure-first environments
  • Teams already using Azure OpenAI
  • Comparing AWS vs Azure quality
  • Organisations with Azure agreements
Route
POST /v1/extract/azure
Requires
Separate Azure deployment (see DEPLOYMENT.md)

Deployment Guide

Get it running on your AWS account

Check off each step as you go — progress is saved in your browser.

⚠️
Do this first — easy to miss: AWS Bedrock requires you to manually enable model access before any API calls work. See Step 2.
✓
Install Terraform and AWS CLI
One-time setup ▼

Install both tools, then restart your terminal.

PowerShell (Windows)
winget install Hashicorp.Terraform
winget install Amazon.AWSCLI
macOS / Linux
brew install terraform awscli

Verify both installed:

Terminal
terraform -version
aws --version
✓
Enable Bedrock model access
AWS Console ▼

This is the most commonly missed step. Without it every Bedrock call returns AccessDeniedException.

  1. Sign in to the AWS Console.
  2. Search Bedrock. Confirm the region top-right is us-east-1 (or your preferred region).
  3. Left menu → Model access → Manage model access.
  4. Enable Anthropic Claude models (Haiku, Sonnet, Opus). Click Save.
  5. Approval is usually instant — the status turns green.
✓
Create an IAM user and configure the CLI
IAM + CLI ▼

Create a user, attach AdministratorAccess, generate a CLI access key, then configure locally:

  1. Console → IAM → Users → Create user (e.g. name it terraform).
  2. Attach policy: AdministratorAccess.
  3. Open the user → Security credentials → Create access key → choose CLI.
  4. Save the Access Key ID and Secret Access Key.
Terminal
aws configure
# AWS Access Key ID:     AKIA…
# AWS Secret Access Key: …
# Default region name:   us-east-1
# Default output format: json
✓
Deploy the backend with Terraform
~30 seconds ▼

cd terraform/aws

cp terraform.tfvars.example terraform.tfvars

Connect the UI to your backend
30 seconds ▼

  2. Click the ⚙️ gear icon top-right.
  3. Paste your api_base_url into API base URL. Click Save.

🔀 How the single Lambda routes all requests

▼

The Lambda reads requestContext.http.method and requestContext.http.path from the API Gateway v2 event and dispatches accordingly. This means one Lambda binary, one IAM role, one CloudWatch log stream — instead of four of each.

handler.py — entry point
def handler(event, context):
    ctx    = event.get("requestContext", {}).get("http", {})
    method = ctx.get("method", "")
    path   = ctx.get("path", "")

    if method == "OPTIONS":
        return {"statusCode": 200, "headers": CORS, "body": ""}

    if path == "/v1/extract/bedrock"  and method == "POST": return handle_bedrock(event)
    if path == "/v1/extract/textract" and method == "POST": return handle_textract(event)
    if path == "/v1/agents/run"       and method == "POST": return handle_agents(event)
    if path == "/v1/logs"             and method == "GET":  return handle_logs(event)

    return respond(404, {"error": "not_found"})

📨 Tab ① Bedrock — sequence diagram

▼
sequenceDiagram participant B as Browser participant G as API Gateway participant L as Lambda participant Bk as Amazon Bedrock participant S as S3 logs B->>G: POST /v1/extract/bedrock
{pdf_b64, target_schema, model} G->>L: proxy event (path + body) L->>Bk: converse(document=PDF, system=rules, text=schema) Bk-->>L: JSON matching schema L->>S: write masked log L-->>B: {result, run_id, latency_ms}

Uses bedrock.converse() with a document content block — Claude reads raw PDF bytes directly. No OCR step.

📨 Tab ② Textract — sequence diagram

▼
sequenceDiagram participant B as Browser participant L as Lambda participant S3i as S3 input participant T as Textract participant Bk as Bedrock B->>L: POST /v1/extract/textract L->>S3i: upload PDF (Textract reads from S3) L->>T: StartDocumentAnalysis(FORMS, TABLES) loop poll every 1.5s L->>T: GetDocumentAnalysis(jobId) T-->>L: status + blocks end L->>L: reconstruct KEY_VALUE_SET pairs L->>Bk: map key/values to schema Bk-->>L: mapped JSON L-->>B: {raw_keyvalues, result}

Textract async API requires the document to come from S3. The Lambda polls up to 20 times (1.5 s apart = max ~30 s) before timing out.

▼
ControlHow it's implemented
No secrets in browserUI only knows the API URL and an optional API key. All AWS calls are inside Lambda.

Troubleshooting

Common issues

🔍
App still shows "Mock mode" after I set the API URL ▼
Check: (1) the URL doesn't have a trailing slash, (2) you clicked Save in the Settings modal, (3) the URL starts with https://. Open browser dev-tools Network tab and look for the actual request URL.
CORS error in the browser console ▼
Your allowed_origin in terraform.tfvars doesn't match the exact origin the browser is using (scheme + domain + port must match). Set it to * for a quick fix, or the exact URL for security. Re-run terraform apply after changing.
Bedrock returns AccessDeniedException ▼
You didn't enable Bedrock model access. Go to the AWS Console → Bedrock → Model access → enable the Anthropic Claude models in the same region as your var.region (default: us-east-1).
Textract job times out / is very slow ▼
Large multi-page PDFs take longer. The Lambda polls up to 20 times at 1.5 s each (~30 s max). Use smaller test PDFs for the demo. For production, consider breaking large PDFs into chunks or using an async pattern with Step Functions.
NoSuchBucket error in Lambda logs ▼
Terraform apply didn't complete, or you're pointing at the wrong region. Check terraform output to see the actual bucket names, and confirm the Lambda's INPUT_BUCKET / LOG_BUCKET env vars match.
Getting 401 Unauthorized from the API ▼
You set api_key in terraform.tfvars but didn't paste the same value in the app's Settings → API key field (or vice versa). Both must match exactly. Leave api_key = "" in tfvars to disable authentication.
Result JSON has all nulls / empty values ▼
(1) The target schema keys don't match the content in your PDF. Try a simpler schema with fewer fields first. (2) The PDF might be image-only (scanned) — use the Textract tab which does true OCR. (3) Try Claude Sonnet or Opus for better accuracy than Haiku.
